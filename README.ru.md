# tbproxy GUI 🐻

Неофициальный клиент TunnelBear для Linux в виде окна на рабочем столе (Flutter).

> **Дисклеймер — неофициальный клиент, только для личного использования.**
> Это независимый клиент TunnelBear, созданный сообществом. Он **никак не
> связан с компанией TunnelBear / McAfee, не создан, не одобрен, не
> проверен и не контролируется ею** — никакого одобрения или надзора с их
> стороны нет. Программа предназначена **для личного использования** теми,
> у кого уже есть аккаунт TunnelBear. Используйте на свой риск.
>
> **Оптимизировано для условий фильтрации в Иране.** **Внутри Ирана этот
> клиент НЕ работает без апстрим-прокси** — прямое соединение с TunnelBear
> заблокировано, поэтому локальный апстрим-прокси должен работать всю
> сессию (заполните блок апстрима в окне или дайте автоопределению найти
> 127.0.0.1:1080/8080). Это **не универсальное средство против фильтрации**:
> оно полезно только тогда, когда у сайта или приложения есть проблема с
> вашим текущим IP — тогда через этот клиент (поверх апстрима) можно
> получить более чистый, подходящий IP через TunnelBear.

## Что это?

Небольшое десктопное приложение, которое запускает тот же CLI `tbproxy`
(подробности в [tbproxy-cli](https://github.com/FossilizedProgrammer/tbproxy-cli/blob/main/README.ru.md)) — без терминала:

- Выпадающий список стран, крупные кнопки **Connect / Disconnect / Check-login**
- Сохранённые email и пароль (в `~/.config/tbproxy-gui/`)
- Переключатели System-wide и Share-on-LAN, блок апстрима со своим
  переключателем вкл/выкл (для блокировок; выкл = всегда напрямую) и живой
  лог всего, что происходит

---

## Что понадобится

1. **Linux с root** (нужен для создания устройства tun).
2. **Go 1.24+** — чтобы собрать CLI, который запускает GUI.
3. **Flutter** с поддержкой Linux desktop — чтобы собрать само окно.
4. **Бинарник `openvpn` (2.5+)** — например `sudo apt-get install -y openvpn`
   или сборка из исходников; полная инструкция в
   [tbproxy-cli](https://github.com/FossilizedProgrammer/tbproxy-cli/blob/main/README.ru.md).

---

## Сборка

Одна команда готовит CLI `tbproxy` (собирает из исходников или сам
скачивает совпадающий релиз), собирает GUI и кладёт `tbproxy` и `openvpn`
рядом с приложением, чтобы папка была самодостаточной:

```bash
./scripts/build-gui.sh
```

Результат: `build/linux/x64/release/bundle/tbgui` (рядом — `tbproxy` и
`openvpn`). Для однофайлового релиза:

```bash
./scripts/build-appimage.sh v1.0.0
```

## Запуск

```bash
./scripts/run-gui.sh
```

Для устройства tun нужен root; скрипт сохраняет ваш дисплей и настройки
(`~/.config/tbproxy-gui/`), поэтому окно появляется как обычно.

---

## Использование

1. Выберите страну (например `de`), введите email и пароль TunnelBear.
2. Нажмите **Connect**. Смотрите в лог, пока туннель не поднимется.
3. Поставьте браузер на **SOCKS5 127.0.0.1:1081** (или HTTP 127.0.0.1:8081).
4. Работайте. Когда закончите — **Disconnect**.

## Блокировки (Иран и т.п.)

**Важно для Ирана: без апстрим-прокси соединения не будет.** Прямые
соединения из Ирана с TunnelBear заблокированы (TLS-хендшейк зависает —
DPI провайдера его убивает), поэтому апстрим **обязателен на всю сессию**.
За пределами Ирана возможны оба случая ниже:

- **Фильтрация есть, но TunnelBear доступен**: просто нажмите Connect —
  апстрим не нужен.
- **Сам TunnelBear заблокирован** (прямое соединение зависает посреди
  TLS-хендшейка — DPI провайдера его убивает): **единственный** способ
  подключения — через локальный апстрим-прокси, и он нужен **на всю
  сессию**, а не только для логина:

  - Запустите любой доверенный прокси-клиент (Psiphon, v2ray, NekoBox, ...),
    чтобы SOCKS/HTTP слушал на `127.0.0.1:1080` / `127.0.0.1:8080`.
  - tbproxy **сам проверяет** эти порты и прогоняет **всё VPN-соединение**
    через прокси (или заполните поля апстрима прямо в GUI).
  - Не хотите апстрим вообще (например, локальный прокси на 1080/8080 не
    должен нести VPN)? Выключите переключатель **Use upstream proxy**:
    поля игнорируются, эти порты не проверяются, а туннель всегда
    подключается напрямую.

**Держите апстрим включённым, пока пользуетесь VPN** — когда TunnelBear
заблокирован, сам туннель идёт через прокси весь это время, поэтому если
прокси умрёт, умрёт и туннель. Не переживайте: tbproxy дождётся возврата
прокси и переподключится сам (в логе: `upstream proxy is down — waiting
for it to come back ...`). Трафик браузера идёт через устройство туннеля
(`tun0`); провайдер может всё ещё замедлять этот путь (медленные
страницы) — это провайдер, а не прокси.
