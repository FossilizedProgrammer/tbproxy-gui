# tbproxy GUI 🐻

کلاینت غیررسمی تانل‌بیر (TunnelBear) برای لینوکس، به‌صورت پنجره‌ی دسکتاپ (فلاتر).

> **توجه — کلاینت غیررسمی، فقط برای استفاده‌ی شخصی.**
> این یک کلاینت مستقل و جامعه‌محور برای تانل‌بیر است. **هیچ ربطی به شرکت
> اصلی TunnelBear / McAfee ندارد** و توسط آن‌ها ساخته، تأیید، نظارت یا
> پشتیبانی نمی‌شود — هیچ تأیید یا نظارتی از طرف آن‌ها در کار نیست. این
> برنامه برای **استفاده‌ی شخصی** کسانی طراحی شده که از قبل اکانت تانل‌بیر
> دارند. استفاده با مسئولیت خودتان.
>
> **برای شرایط فیلترینگ ایران بهینه شده.** **در ایران بدون آپ‌استریم کار
> نمی‌کند** — اتصال مستقیم به تانل‌بیر بسته است، پس باید در کل جلسه یک
> پروکسی آپ‌استریم محلی روشن باشد (بخش upstream پنجره را پر کن یا بگذار
> 127.0.0.1:1080/8080 خودکار پیدا شود). این ابزار **راه‌حل کلی ضدفیلتر
> نیست**: فقط مناسب این است که اگر سایت یا اپلیکیشن مورداستفاده با آی‌پی
> شما مشکل داشته باشد، آن‌وقت می‌شود از این کلاینت (روی آپ‌استریم) استفاده
> کرد تا آی‌پی مناسب‌تری از طریق تانل‌بیر داشت.

## این چیست؟

یک اپ کوچک دسکتاپ که همان CLI یعنی `tbproxy` را اجرا می‌کند (توضیحات کامل در
[cli/README.fa.md](../cli/README.fa.md)) — بدون ترمینال:

- دراپ‌داون کشور، دکمه‌های بزرگ **Connect / Disconnect / Check-login**
- ذخیره‌ی ایمیل و رمز عبور (در `~/.config/tbproxy-gui/`)
- سوییچ‌های System-wide و Share-on-LAN، بخش آپ‌استریم با سوییچ روشن/خاموش
  (برای شبکه‌های فیلترشده؛ خاموش = همیشه اتصال مستقیم) و یک لاگ زنده از
  همه‌ی اتفاق‌ها

---

## چه چیزهایی لازم داری

1. **لینوکس با دسترسی root** (برای ساخت دستگاه tun لازم است).
2. **Go نسخه ۱.۲۴ یا بالاتر** — برای ساخت CLI که GUI اجرااش می‌کند.
3. **فلاتر** با پشتیبانی Linux desktop — برای ساخت خود پنجره.
4. **باینری `openvpn` (نسخه ۲.۵ به بالا)** — مثلاً
   `sudo apt-get install -y openvpn` یا ساخت از روی سورس؛ راهنمای کامل در
   [cli/README.fa.md](../cli/README.fa.md).

## ساخت

یک دستور هم CLI را می‌سازد، هم GUI را، و `tbproxy` را کنار اپ می‌گذارد تا
پوشه خودکفا باشد:

```bash
./gui/scripts/build-gui.sh
```

خروجی: `gui/build/linux/x64/release/bundle/tbgui`

---

## اجرا

```bash
./gui/scripts/run-gui.sh
```

برای دستگاه tun به root نیاز است؛ اسکریپت دیسپلی و تنظیمات خودت
(`~/.config/tbproxy-gui/`) را حفظ می‌کند تا پنجره درست ظاهر شود.

---

## استفاده

۱. کشور را انتخاب کن (مثلاً `de`)، ایمیل و رمز تانل‌بیر را بزن.
۲. **Connect** را بزن. در لاگ بمان تا تونل وصل شود.
۳. مرورگرت را روی **SOCKS5 با آدرس 127.0.0.1 و پورت 1081** بگذار
   (یا HTTP با پورت 8081).
۴. بگرد. تمام که شدی **Disconnect** بزن.

## فیلترینگ (ایران و شبیه آن)

**نکته‌ی مهم برای ایران: بدون پروکسی آپ‌استریم هیچ اتصالی برقرار نمی‌شود.**
اتصال مستقیم از ایران به تانل‌بیر بسته است (دست‌دادن TLS می‌خوابد —
فیلترینگ ISP آن را قطع می‌کند)، پس آپ‌استریم **در کل جلسه اجباری است**.
خارج از ایران هر دو حالت زیر ممکن است:

- **فیلترینگ هست ولی تانل‌بیر باز است**: مستقیم Connect بزن — آپ‌استریم
  لازم نیست.
- **خودِ تانل‌بیر فیلتر است** (اتصال مستقیم وسط دست‌دادن TLS می‌خوابد —
  فیلترینگ ISP آن را قطع می‌کند): تنها راه وصل شدن، پروکسی آپ‌استریم
  محلی است و باید **کل جلسه** روشن بماند، نه فقط موقع لاگین:

  - هر کلاینت پروکسی که بهش اعتماد داری اجرا کن (Psiphon، v2ray،
    NekoBox، ...) طوری که SOCKS/HTTP روی `127.0.0.1:1080` /
    `127.0.0.1:8080` گوش بدهد.
  - tbproxy **خودکار** این پورت‌ها را چک می‌کند و **کل اتصال VPN** را
    از پروکسی رد می‌کند (یا خودت آدرس را در بخش upstream همان GUI پر کن).
  - اگر اصلاً نمی‌خواهی آپ‌استریمی در کار باشد (مثلاً پروکسی محلی روی
    1080/8080 نباید تونل را حمل کند)؟ سوییچ **Use upstream proxy** را
    خاموش کن: فیلدها نادیده گرفته می‌شوند، این پورت‌ها اصلًا چک نمی‌شوند
    و تانل همیشه مستقیم وصل می‌شود.

**تا وقتی از VPN استفاده می‌کنی، آپ‌استریم را روشن نگه دار** — وقتی
تانل‌بیر فیلتر است، اتصال تانل خودش روی پروکسی سوار است؛ اگر پروکسی
بمیرد، تانل هم می‌میرد. نگران نباش: tbproxy صبر می‌کند تا پروکسی
برگردد و خودش دوباره وصل می‌شود (در لاگ: `upstream proxy is down —
waiting for it to come back ...`). ترافیک مرور از دستگاه تونل (`tun0`)
می‌رود؛ ممکن است ISP همان مسیر را کند کند (صفحات آهسته باز شوند) —
تقصیر ISP است، نه پروکسی.
